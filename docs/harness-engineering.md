# ハーネスエンジニアリング

## ハーネスエンジニアリングとは

AIエージェントを安全・一貫・効率的に動作させるために、エージェントを取り巻く仕組み（ハーネス）を設計する手法。

```
Agent = Model + Harness
```

- **Model**: 知能（LLM本体）
- **Harness**: その知能を実用的にする仕組み全体

ハーネスがなければLLMはただのチャットボット。ハーネスがあることで、自律的に動くコーディングエージェントになる。

## Claude Code のハーネス構成要素

### CLAUDE.md（永続的な指示）

- 全セッションで読み込まれるプロジェクトの指示書
- コードスタイル、ビルドコマンド、アーキテクチャ判断等を記載
- `@path/to/file` で外部ルールファイルを参照可能
- スコープ: グローバル（`~/.claude/CLAUDE.md`）、プロジェクト（`.claude/CLAUDE.md`）

### Rules（整理された指示）

- `.claude/rules/` に配置
- CLAUDE.md から `@.claude/rules/filename.md` で参照
- 常時コンテキストに読み込まれる
- 用途: コーディング規約、設計方針、セキュリティルール等

### Skills（オンデマンドの知識・ワークフロー）

- `.claude/skills/<skill-name>/SKILL.md` に配置
- ユーザーが `/skill-name` で明示的に呼び出したときだけ読み込まれる
- 呼び出すまでトークンを消費しない
- 2種類:
  - **参照型**: 規約、パターン、ドメイン知識（Claudeが必要に応じて参照）
  - **タスク型**: ステップバイステップのワークフロー（`/deploy` 等）

### Hooks（確定的な自動化）

- 特定のライフサイクルイベントで自動実行されるスクリプト
- CLAUDE.mdの指示（助言的）と異なり、**実行が保証される**
- 主なイベント: `PreToolUse`, `PostToolUse`, `Stop`, `SessionStart` 等
- 用途: 自動フォーマット、ファイル保護、通知、環境変数リロード等

### Settings & Permissions

- `.claude/settings.json` で設定
- Claudeが確認なしで実行できる操作を制御
- deny/allowパターンで権限を管理

### MCP（Model Context Protocol）

- 外部サービスとの統合（GitHub、DB、Figma等）
- `.claude/mcp.json` で設定
- Claudeがビルトインツールのように使える

### Subagents（委譲コンテキスト）

- `.claude/agents/<agent-name>.md` で定義
- 独立したコンテキストウィンドウで動作
- 調査、検証、並列作業に利用
- メインコンテキストの肥大化を防ぐ

## 各コンポーネントの使い分け

```
ルールが:
├─ 全セッションで適用すべき?
│  ├─ 情報的（スタイルガイド等）→ Rules / CLAUDE.md
│  └─ 確定的に強制すべき → Hook
│
├─ 必要なときだけ読み込む?
│  ├─ ワークフロー（/deploy等）→ Skill（タスク型）
│  └─ ドメイン知識 → Skill（参照型）
│
└─ 外部サービス連携? → MCP
```

| コンポーネント | 読み込み | 強制力 | 用途 |
|---|---|---|---|
| Rules | 常時 | 助言的 | コーディング規約、設計方針 |
| Skills | オンデマンド | 助言的 | ワークフロー、ドメイン知識 |
| Hooks | 自動 | 確定的 | フォーマット、バリデーション、通知 |
| MCP | 常時 | ツール提供 | 外部サービス統合 |

## 何がそれを変えてよいかで分ける

ルールや値は、「何がそれを変えてよいか」で 3 つに分ける。層によって守り方と担い手が変わる。

| 層 | 変えてよいもの | 例 | 守り方 | 正本 |
|---|---|---|---|---|
| 1. 固定 | 人の決定だけ | 型・lint の規約、秘密の値の扱い、データの保護、権限の範囲 | ツールとフックで機械的に止める。変えるのは人が決めたときだけ | 上の「各コンポーネントの使い分け」、`docs/coding-standards.md` |
| 2. 外の事実 | 外の世界 (相手が仕様を変える) | 外部 API の仕様・レート制限・エラーの意味・料金、提携先の規約、法令で決まる値 | 値は 1 か所に出どころと確認日を付けて置き、プロジェクトの前提の台帳に 1 行足す。実行時に照合して、食い違えば止まる形にできるなら、注記よりそちらを選ぶ | 各プロジェクトの前提の台帳 |
| 3. 観測で変える | 観測した結果 (決まった手順を通して) | 本番の指標で決める閾値、性能の予算、実験の結果で採否を決める機能 | 判断の基準を、結果を見る前に書いて固定する。その手順を通してだけ変え、結果を見てから基準を動かさない | ADR の再評価の条件と `review_by` (`docs/adr-guideline.md`) |

AI が起こしやすい失敗は、層ごとに違う。

- 1 を動かす: 結果を見てから、基準やルールを緩める。-> フックで止め、変更は提案して止まる
- 2 を固定のまま使う: 外の事実を記憶や古い確認のまま書き、相手が変えても気づかない。-> 記憶で書かせず、出どころと確認日を必須にし、照合で止める
- 3 を場当たりに変える: 途中の結果を見て値を調整する。-> 基準を先に固定する手順を通す

ツールが既に追っているもの (lockfile の版、`engines`、browserslist、依存の更新の bot) は 1 として扱い、台帳には載せない。

機械向けの要約は `.claude/rules/change-authority.md`。既存のプロジェクトでは、初めて読んだセッションで採用するかを 1 回だけ確かめ、答えをそのプロジェクトの CLAUDE.md に記録する。

## ベストプラクティス

### CLAUDE.md

- 「これを外すとClaudeがミスするか？」で判断。Noなら削る
- Claudeがコードから推測できることは書かない
- 長い手順はSkillsに移動してトークンを節約

### Rules

- 短く、具体的に
- 「常に守るべきルール」のみ
- プロジェクト固有のスタイルはここに

### Skills

- 参照型: descriptionでClaudeが「いつ使うか」を判断できるように
- タスク型: 副作用がある場合は `disable-model-invocation: true`
- SKILL.md は500行以内に収める

### Hooks

- 破ってはならないルール（ファイル保護等）はHookで強制
- フォーマッタの自動実行に最適
- 終了コード2でアクション自体をブロック可能

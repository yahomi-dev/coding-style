# 文書の表記と用語 (機械向けの要約)

正本は coding-style リポジトリの `docs/wording-guideline.md`。ここは、返答、コミットメッセージ、PR / MR、設計書、コメント、図のラベルを書くときに守る要点だけ。

## 用語

- 判定の問い: その分野の技術者が、自分で書くときに使う呼び名か。技術者が通常使う漢語とカタカナ語で書く
- 和語の言い換え、漢字 1 字の造語、比喩の動詞を使わない。過去の文書やメモに同じ語があっても、新しく書く文に持ち込まない
- プロジェクトに用語集があれば、用語集の語を優先する。引用と、相手の文面に合わせる語はそのまま使う
- 図の関係のラベルは短い動詞 (指す、持つ、受ける)。名詞句の説明をラベルにしない

| 使わない | 使う |
|---|---|
| 確かめる / 直す / 足す / 作る / 消す | 確認する / 修正する / 追加する / 作成する / 削除する |
| 戻す (データ) / 見張る / 受け持つ | 復元する / 監視する / 担当する |
| 建てる (環境) / 流す (コマンド) | 構築する / 実行する |
| 組 / 手 / 見立て | 組み合わせ / 方法、選択肢 / 推測、見解 |
| 置き場所 / 鍵 / 写し / 台本 | 保存先 / 認証情報 / コピー / スクリプト |
| 印 / 段 / 版 / 題 | 属性 / ステップ / バージョン / タイトル |
| 普段どおり / 効く / 崩れ | 通常どおり / 機能する、適用される / レイアウト崩れ |
| 引く、引き当てる | 量は「求める、算出する」、行や値は「取得する、参照する」、キーで 1 件は「特定する」、条件で複数は「抽出する」 |
| 弾く | 受け付けない、エラーとする、拒否する |
| 渡す (値を API に送る) | 指定する |
| 状態コード / 失敗の種類 / 要求、応答 | HTTP ステータスコード / エラーコード / リクエスト、レスポンス |

## 表記

- 括弧は半角 `()`。全角の括弧は使わない
- 矢印は `->` `<-`。Unicode の矢印は使わない
- 日付は `YYYY-MM-DD`。時刻は JST で書く (UTC の出力は JST に換算する)
- 英数字と日本語の間に半角スペースを入れる。ただし、既存の文書が空白を入れない表記で統一されているときは、そちらに合わせる

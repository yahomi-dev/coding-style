# コードスタイルの共通ルール

## 基本方針
- 既存コードのスタイルを優先する(プロジェクトのフォーマッタと lint の設定に従う。例: biome.json)
- 修正箇所以外のフォーマットを変えない
- import の追加は既存の並び順に合わせる

## 命名
- 変数・関数: camelCase
- 型・クラス: PascalCase
- 定数: UPPER_SNAKE_CASE
- ファイル名: プロジェクトの既存パターンに合わせる

## コメント
- 修正したコードにだけコメントを追加する(既存コードにコメントを追加しない)
- 自明なコードにはコメント不要
- TODO を残す場合は理由を書く
- コメントは 1 文 1 行で書く (1 行に複数の文があるコメントは `pnpm comments:check` が検出する)  
  文の途中で手動改行して折り返さない(折り返しはエディタや GitLab の diff UI に任せる。行長 lint がコメントに及ぶ場合のみ例外)

## 検査
- 検査は、プロジェクトの検証コマンド (lint、ast-grep、型検査、テストをまとめて実行するもの。例: `just verify`、`pnpm verify`) で行う  
  `npx` などで個々のツールを直接実行しない

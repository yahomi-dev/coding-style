# 外向けの文書のルール (機械向けの要約)

正の文書は coding-style リポジトリの `docs/outward-writing.md`。ここは、コミットメッセージ、PR / MR のタイトルと本文、コミットされるファイル、リリースノートなど、リポジトリの外の読み手に届く文書を書くときに守る要点だけ。用語と表記は `wording.md` に従う。

## 判断基準

- このリポジトリだけを見た新規参加者が、追加の文脈なしに理解でき、疑問や混乱が残らないか。残るなら、書かないか、単体で読めるように書き換える

## 書かないもの

1. git 管理外のローカルのパスとファイル名 (作業メモ、個人用の設定ファイル、バックアップの保存先、一時ディレクトリ、個人のマシンの絶対パス)
2. 無関係なリポジトリ名と、個人環境の固有名詞
3. 内部ラベルと、文脈に依存する参照 (作業サイクルやフェーズの番号、課題の ID、「前回の調査」)。索引をリポジトリに同梱した場合だけ可
4. 作業の手段の話 (AI のエージェント、セッション、スキルの名前、設定)
5. シークレットの値や所在を推測できる情報
6. 出所を前提にした説明 (「翻訳した」「移植した」)

- 公開リポジトリでは、非公開の組織やプロジェクトを特定できる名前 (プロジェクト名、サービス名、ホスト名、アカウントの識別子、人名) も書かない。例は架空の汎用的なものにする
- 4 の例外: エージェント向けの指示のファイル (CLAUDE.md、AGENTS.md、`.claude/` の rules と skills) は作業の手段そのものを扱うので、4 を適用しない

## 書き方

- 結論と根拠だけを、単体で読める形で書く。経緯と内部の文脈は、ローカルのメモに残す
- 参照は、リポジトリに実在するもの (ファイルのパス、ADR の番号とタイトル、同じリポジトリの Issue や PR / MR の番号) を指す
- 書き終えたら、上の 1〜6 で走査してから出す

## コミットメッセージ

- Conventional Commits: `<type>(<scope>): <subject>`。type は feat / fix / docs / refactor / test / chore
- scope は、変更したサービスやパッケージの名前。subject は日本語可で、100 文字以内
- `Co-Authored-By: Claude ...` などの AI のトレーラーを付けない

## PR / MR

- 本文に「設計からずらした点」(設計書や ADR と異なる実装と、その理由) と「要判断」(判断を求める点。選択肢と推奨つき) の欄を設ける。該当がないときは「なし」と書く
- "Generated with Claude Code" の形式のフッターを付けない

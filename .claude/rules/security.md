# セキュリティのルール

守る主体ごとに分けて書く。  
「仕組み」の列は、ルールを機械的に守るための設定と検査である。  
仕組みが無いルールは、レビューで確認する。

## AI が守るルール

| ルール | 仕組み |
|---|---|
| `.env` と `.env.*` のファイルを読まない、編集しない (`.env.example` は読んでよい) | `.claude/settings.json` の `permissions.deny` と、PreToolUse の hook (`scripts/hooks/deny-env-access.ts`) |
| 認証情報のファイル (credentials、token など) を読まない、編集しない | `permissions.deny` に、対象のパスを登録する |
| 新しいパッケージを追加する前に、ユーザーに確認する | なし<br>lockfile の差分を、MR のレビューで確認する |

`.env` の保護は 2 つの仕組みを重ねる。

- `permissions.deny`: よく使う名前 (`.env`、`.env.local`、`.env.production` など) を、Read と Edit の対象から外す
- hook: 名前が `.env` か `.env.` で始まるファイルを、Read、Edit、Write、Grep、Glob、Bash で拒否する  
  Bash は、コマンドの引数にファイルの名前があるときに拒否する

hook が拒否できないのは、ファイルを名指ししないコマンド (例: `grep -r pattern .`) と、スクリプトの中でファイルを開く処理である。  
この範囲まで拒否するには、Claude Code のサンドボックスを使う。

## 人と AI が守るルール

### シークレットとデータ

| ルール | 仕組み |
|---|---|
| シークレットと API キーをコードに書かない | シークレットの検査 (`pnpm secrets:check`。検証コマンドと、コミットの前に実行する)<br>`.env` を `.gitignore` に入れる |
| ログに機微な情報を出力しない | なし |
| 実データ (顧客名、氏名、メールアドレス、本番の記録) をリポジトリに置かない<br>セッションにも貼り付けない | 手元の実データのディレクトリを `.gitignore` に入れる |
| テストと動作の確認には、架空のデータを使う<br>メールアドレスは `example.com` のドメインにする | なし |

### 入力の検証

| ルール | 仕組み |
|---|---|
| 外部からの入力は、境界でパースしてから内部に渡す | zod のスキーマと `*.parse.ts`<br>ast-grep の `no-as-cast` が、パースを通さない型の付与を検出する |
| 入力の検証は、バックエンドを正とする<br>フロントエンドの検証は利用者への通知のためで、省略されても安全にする | なし |
| 形式の検証 (必須、長さ、書式) は、契約のスキーマを 1 つ定義し、フロントエンドとバックエンドで同じスキーマを使う<br>同じ検査を 2 回書かない | 契約のスキーマ (zod) を、両方から読み込む |
| 実行時にしか分からない検証 (重複、存在、権限、状態) は、バックエンドだけが行う<br>フロントエンドは、返されたエラーを表示する | なし |
| SQL はパラメタライズドクエリを使う (ORM が処理する場合は可) | なし |
| HTML の出力はサニタイズする | フレームワークの自動エスケープ<br>React では Biome の `noDangerouslySetInnerHtml` |
